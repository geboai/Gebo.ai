# Copying agents, networks of agents and prompts: implementation plan

Status: **plan only, nothing implemented**. Written 2026-10-06 against `develop` at `c0b352e91`.

## 1. Goal and rules

The agents and networks of agents generated by configuration (the standard ones) are read-only. They are meant to be **copied and then customized**. Prompts need the same capability.

These rules come from the product owner:

1. **Every copy is a new object with a newly generated code.** The source is never changed.
2. **A network of agents can be copied.** The copy keeps the source's topology and attributes, which can then be changed, and **keeps referring to the existing agents**.
3. **Agents are copied on write inside a network.** When an admin changes an agent's attributes or prompt *while editing a network*, the agent is copied. The copy, with its new code, then replaces the original **in that network only**.
4. **A prompt can be copied.**

## 2. Current state (grounded in the code)

### 2.1 Agents: `GAgentConfig`
- **Model:** `gebo.architecture.parent/gebo.architecture.agents.abstraction.layer/.../agents/model/GAgentConfig.java`. It extends `GBaseObject` and implements `IJsonClonable<GAgentConfig>`.
- **Fields that matter for a copy:**
  - `readOnly`;
  - `defaultConfiguration`: `IGGenericAgentService.getDefaultConfiguration()` takes the first config of a service with this flag set;
  - `agentType` (`AGENT` or `AGENTS_NETWORK`) and `adaptedAgentNetworkCode`;
  - the prompt, either shared by use (`mainLoopPromptUseCode`) or embedded (`customLoopPrompt`);
  - `chatModelReference`, `enabledFunctions`;
  - the ACL: `accessibleToAll`, `accessibleGroups`, `accessibleUsers`, `aclAliases`.
- **DAO:** `services/impl/AgentConfigDaoImpl.java` implements `IAgentConfigDao`. It merges two sources:
  - configuration-generated agents (`IGDynamicAgentConfigDataSource`), served as `jsonClone()` copies marked `readOnly=true`;
  - agents saved in Mongo (`AgentConfigRepository`).
  - Insert, update and delete throw if `readOnly` is true.
- **REST:** `controllers/GeboAgentAdminController.java` at `api/admin/GeboAgentAdminController`, `@PreAuthorize("hasRole('ADMIN')")`.
  - Endpoints: `getAgentByCode`, `insertAgent`, `updateAgent`, `deleteAgent`, `getAgents`.
  - `insertAgent` goes straight to `agentsConfigDao.insert`, with no extra validation.

### 2.2 Networks: `GAgentsNetwork`
- **Model:** `agents/model/GAgentsNetwork.java`. It extends `GBaseObject` and implements `IJsonClonable<GAgentsNetwork>`. It has `readOnly` and the ACL fields.
- **Participants** (`AgentNetworkParticipant`):
  - `agentConfigCode` refers to the agent by code;
  - `communicationList` lists the participant names this participant can reach.
  - A participant's name is `getNetworkAgentName()`, i.e. `agentConfigCode` plus `-contextualName` when set.
  - **So changing a participant's `agentConfigCode` renames it, and every `communicationList` that points to it must be rewritten.**
- **DAO:** `services/impl/AgentNetworkConfigDaoImpl.java` implements `IAgentsNetworkDao`. It has the same two sources and `readOnly` handling as the agent DAO.
- **CRUD service:** `services/impl/GAgentsNetworkCrudServiceImpl.java` implements `IGAgentsNetworkCrudService`. It provides `validate`, `insert`, `update` and `delete`, each returning `OperationStatus`.
  - `insert` refuses a code that already exists.
  - `validateStructure` checks that every participant's agent config exists (`:293`) and that its agent service exists (`:305`).
  - `validateCommunicationEdges` checks the communication lists.
  - Update and delete refuse `readOnly` networks.
- **REST:** `controllers/GeboAgentsNetworkAdminController.java` at `api/admin/GeboAgentsNetworkAdminController`, ADMIN only.
- **Built-in networks** are created read-only in `gebo.architecture.agents.standard`: `StandardAgentsInitialization.java:291` and `AgenticLoopAgentsInitialization.java:110`.

### 2.3 Prompts: `GPromptTemplateConfig`
- **Model:** `gebo.architecture.parent/gebo.architecture.ai/.../ai/model/GPromptTemplateConfig.java`. It is a Mongo `@Document`, **not** a `GBaseObject`.
  - It implements `Cloneable` (`clone()` at `:179`).
- **Its code is computed, not generated:** `regenerateCode()` builds `promptUse-langCode-modelProvider-modelCode`. A prompt's identity is therefore its use, language and model.
- **DAO:** `service/impl/GPromptConfigDaoImpl.java` implements `IGPromptConfigDao`.
  - Library prompts have `configDeclarated=true` and are read-only: `insert`, `update` and `delete` throw at `:200`, `:207` and `:214`.
  - Lookup prefers a saved (non-declared) prompt over a library prompt with the same code (`:191`).
  - **So saving a copy of a library prompt with the same use, language and model overrides the library prompt.**
  - **And saving a copy of a saved prompt with the same keys overwrites it**, because the Mongo `_id` is the code.
- **REST:** `gebo.ragsystem.parent/gebo.ragsystem.client.rest/.../controllers/GeboAdminPromptsController.java` at `api/admin/GeboAdminPromptsController`, ADMIN only. Endpoints: `findPromptConfigByCode`, `insertPromptConfig`, `updatePromptConfig`, `deletePromptConfig`.

### 2.4 Code generation for `GBaseObject`
- `GPersistentObjectManagerImpl.insert` (`gebo.architecture.persistence/.../impl/GPersistentObjectManagerImpl.java:465`) only accepts objects without a code.
- It generates one from the description (`generateUniqueCode`, `:259`): lowercased, spaces become `-`, and a random suffix is added while the code is taken.
- It also sets `dateCreated`.
- **So a copy only needs `code = null` and a description.**

## 3. Design

### 3.1 A shared service, so copy rules live in one place
- **New interface:** `IGAgentsCopyService` in `gebo.architecture.agents.abstraction.layer/.../agents/services/`.
- **Implementation:** `services/impl/GAgentsCopyServiceImpl.java`.
- **Methods:**

| Method | Persists | Returns | Purpose |
|---|---|---|---|
| `copyTemplateOfAgent(String code, String description)` | no | `GAgentConfig` | an unsaved copy: no code, `readOnly` and `defaultConfiguration` cleared, audit fields cleared, description set |
| `copyAgent(String code, String description)` | yes | `GAgentConfig` | the template above, inserted through `IAgentConfigDao.insert`, which generates the code |
| `copyAgentsNetwork(String code, String description)` | yes, through the CRUD service | `OperationStatus<GAgentsNetwork>` | the network copy |

- **Rules for `copyTemplateOfAgent`:**
  - Load through `IAgentConfigDao.findByCode`, which also returns configuration-generated agents. Throw "not found" if missing.
  - `jsonClone()`, then:
    - `setCode(null)`, `setReadOnly(null)`, `setDefaultConfiguration(null)`;
    - `setDateCreated/DateModified/UserCreated/UserModified(null)`.
  - Description: the given one, or `"Copy of " + source.getDescription()`.
  - Everything else is kept: service, role, prompt (shared or embedded), model reference, tools, thinking, temperature, iterations, ACL (see decision D2).
- **Rules for `copyAgentsNetwork`:**
  - Load through `IAgentsNetworkDao.findByCode`.
  - `jsonClone()`, then `setCode(null)`, `setReadOnly(null)`, and clear the audit fields.
  - Description: the given one, or `"Copy of …"`.
  - Participants are kept as they are: same agents, same `communicationList`. Rule 2: the copy refers to the existing agents.
  - Insert through `IGAgentsNetworkCrudService.insert`, so the standard validation runs.

### 3.2 REST endpoints (ADMIN, inside the existing controllers)
- **`GeboAgentAdminController`:**
  - `GET getAgentCopyTemplate?code=&description=` returns an unsaved `GAgentConfig`.
  - `POST copyAgent` takes `{code, description}` and returns the saved `GAgentConfig`.
- **`GeboAgentsNetworkAdminController`:**
  - `POST copyAgentsNetwork` takes `{code, description}` and returns `OperationStatus<GAgentsNetwork>`, like the other CRUD endpoints.
- **`GeboAdminPromptsController`:** `POST copyPromptConfig` (see 3.4).
- **Request bodies:**
  - New small DTO `CopyRequest { String code; String description; }`, next to the controllers.
  - For prompts: `PromptCopyRequest { String code; String langCode; String modelProvider; String modelCode; }`.

### 3.3 Copy on write inside the network editor (rule 3)
This is a UI-side flow and needs no network endpoint. The network is saved by the existing `updateAgentsNetwork`.

1. **The participant's edit action** (`editAgentConfig`, in the participant dialog and on the diagram node) asks for the unsaved template:
   - `getAgentCopyTemplate(code, description = "<agent description> (<network description>)")`.
2. **It opens the agent editor with `actionType: NEW`** and the template as `target`, the same way `addAgentConfig()` already opens a new agent.
   - The admin changes the attributes and/or the prompt.
   - **Prompt:** it stays as the source has it (shared by `mainLoopPromptUseCode`, or embedded in `customLoopPrompt`). A change made in the editor goes to the copy's own `customLoopPrompt`, so the shared prompt is untouched.
3. **`onActionPerformed`, when the copy was saved,** gives the new code (`event.target.code`, as `addAgentConfig` already reads). Then, in the network being edited:
   - `oldName = participant.networkAgentName`;
   - set `participant.agentConfigCode = newCode`, keeping `agentContextualName`;
   - `newName` is recomputed the same way as the backend (`agentConfigCode` plus `-contextualName`);
   - in **every** participant, replace `oldName` with `newName` in `communicationList`;
   - `updateFormGroup()` marks the network dirty and redraws the diagram;
   - `loadAvailableAgents(newCode)` refreshes the select.
4. **The admin saves the network** as usual (`updateAgentsNetwork`). Validation then sees the new agent code, which exists because it was saved.
5. **Cancel in the agent editor** inserts nothing, so no orphan agents are left.
6. **A read-only network** cannot be edited (the existing `readonly` flag). The admin first copies it (3.5), then edits the copy's agents with this flow.

The name rewrite goes in one small pure helper in the network editor (`renameParticipant(agents, oldName, newName)`), so it can be unit-tested.

### 3.4 Copying a prompt
- **Endpoint:** `POST copyPromptConfig(PromptCopyRequest)`, implemented in a new method of `IGPromptConfigDao`/`GPromptConfigDaoImpl`, or a small `GPromptCopyService` in `gebo.architecture.ai`.
- **Steps:**
  1. Load by code. The source may be a library or a saved prompt.
  2. `clone()`, then `setConfigDeclarated(null)`.
  3. Apply the target `langCode`, `modelProvider` and `modelCode`; a null keeps the source value. The code is recomputed (`regenerateCode()` runs through the setters).
  4. **Collision rule:**
     - if a **saved** prompt already has the target code, refuse with an error (no silent overwrite);
     - if only a **library** prompt has it, allow it: this is the "override a library prompt" case, stated in the response message.
  5. Insert through the DAO.
- **Copying a prompt into an agent** is covered by 3.3 (the copy's `customLoopPrompt`). No extra endpoint is needed.

### 3.5 UI actions
- **Networks list** (`agent-networks.component.html`):
  - a "copy" button per row, next to "configure";
  - it opens a small dialog asking for the description, default "Copy of <description>";
  - it calls `copyAgentsNetwork`, then opens the copy in the network editor (OPEN with the new code).
- **Network editor:** the participant edit action becomes the copy-on-write flow in 3.3. The "edit" title or tooltip says that a copy is created for this network.
- **Agent editor** (`gebo-ai-agents-admin`):
  - a "copy" button in the toolbar, enabled also when the agent is read-only;
  - it calls `copyAgent` and opens the copy;
  - this is how a standalone generated agent gets customized, since there is no agents list panel.
- **Prompts list** (`prompts-panel.component.html`):
  - a "copy" button per row;
  - it opens a dialog with the target language and model provider/model, prefilled with the source's;
  - it calls `copyPromptConfig`, then opens the copy in the prompt editor;
  - on a collision error the dialog shows the message.
- **i18n:** every new element gets an `id` and `gebo-ai-label`/`gebo-ai-text`, with entries in `gebo-ai-reusable-ui/src/assets/i18n/en.json` under the components' module/entity, following `.claude/skills/i18n-component-resources`.

## 6. Risks and notes
- **Name rewrite:** the backend computes the participant name as `agentConfigCode + "-" + agentContextualName` (`GAgentsNetwork.java`). The UI rewrite must use the same formula, otherwise `validateCommunicationEdges` rejects the network on save.
- **Default configuration:** a copy must never keep `defaultConfiguration=true`. Otherwise it competes with the source as its service's default (`IGGenericAgentService.getDefaultConfiguration` takes the first one).
- **Copy chains:** with "always copy on write", editing the same participant twice in a network creates a copy of the copy (see D1).
- **Prompt overwrite:** the explicit collision check is what keeps the copy from becoming a silent `save` over an existing prompt.
- **Microservices:** until the brain clients are regenerated, the microservices UI cannot call the new endpoints.

## 7. Decisions pending (default proposed in bold)
- **D1, repeated edits in a network.** Copy only when the participant's agent is read-only or is also referenced by another network; otherwise edit it in place. **Or** always copy, as rule 3 literally says, accepting copy chains. *Proposed default: copy only when read-only or shared.*
- **D2, ACL of a copy.** **Keep the source's ACL** (`accessibleToAll`, groups, users, aliases), or start restricted to admins.
- **D3, prompt copy target.** **Language and model provider/model only**, or also allow changing `promptUse`.
- **D4, side finding.** `addAgentConfig()` in the network editor creates new agents with `defaultConfiguration: true` (`gebo-ai-agents-network-admin.component.ts:431`). That can make a new agent its service's default. **Fix it in this work** (set it to null), or leave it.
- **D5, branch.** **A new branch from `develop`** (e.g. `feature/copy-agents-networks-prompts`), announced to the Windows box session working on `feature/agent-tools-improvements`.
