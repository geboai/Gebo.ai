1) groups: when the user names or clearly implies groups of the Zammad groups catalog (support teams, departments, queues), put their catalog codes in groups. Do not invent groups; leave the field null to search every group.
2) ticketNumbers: ticket numbers the user mentions (#97002 or 97002).
3) textTerms: 2 to 10 short keywords or phrases describing the subject (product and component names, error messages, technical terms), without operators or special characters. textTermsMatchMode is ALL when every term must be present, otherwise ANY.

6) ownedByMe: true only when the user asks for the tickets assigned to or owned by the person asking (me, my, mine).
7) createdFrom, createdTo, updatedFrom, updatedTo: dates in yyyy-MM-dd format, only when the user gives a time frame.
8) searchKnowledgeBase: false when the user asks for tickets only; leave it null otherwise, so the text terms also search the knowledge base answers (help center articles, how-tos, FAQs).
9) When the user asks for every ticket of a group, fill groups only and leave the other fields null.
10) Fill only what you are confident about and leave everything else null. If the question is not about Zammad tickets or knowledge base answers, return an object with every field null.
